# 022 项目任务链路与 Docker 一键启动

> 日期：2026-09-14  
> 状态：已完成

## 目标

- 让项目、资产和生成任务形成可理解的项目工作流。
- 移除中断后遗留基础设施容器的本地启动脚本，提供完整 Docker Compose 测试环境。

## 实现内容

- 创建项目成功后直接进入绑定 `projectId` 的白底精修工作台。
- 项目卡显示资产数和任务数，提供“进入创作”和“查看任务”入口。
- 任务列表支持 `projectId` 筛选，项目任务页返回项目入口并保留项目上下文。
- 上传资产和创建生成任务时更新项目 `updated_at`，项目排序能反映真实活动。
- 根目录 Compose 统一编排 PostgreSQL、Redis、Go API 和 Next.js Web，服务通过健康检查控制启动顺序。
- PostgreSQL 和 Redis 仅在 Compose 内部网络开放，避免与宿主机现有数据库服务发生端口冲突。
- 删除 `scripts/start-test.sh` 和旧的 `infra/docker/docker-compose.yml`，避免出现两套启动入口。
- 增加 API/Web Dockerfile、持久化上传卷和 `.dockerignore`。

## 遗留问题

- 项目目前仍未提供项目重命名、归档和删除能力，暂不增加破坏性操作。
- 项目详情仍复用工作台和任务筛选页，尚未独立建设项目概览页。
- Compose 默认不包含供应商密钥，需要通过根目录 `.env` 或环境变量提供 `BANANA_ROUTER_API_KEY`。
- Docker Compose 负责数据持久化；执行 `docker compose down -v` 会删除测试数据库、Redis 和上传数据。
