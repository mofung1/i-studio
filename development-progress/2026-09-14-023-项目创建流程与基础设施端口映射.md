# 023 项目创建流程与基础设施端口映射

> 日期：2026-09-14  
> 状态：已完成

## 目标

- 恢复 PostgreSQL 和 Redis 的宿主端口映射，方便本地调试和查看数据。
- 从高级产品和用户体验角度明确“项目”和“任务”的边界，避免继续叠加冲突入口。

## 实现内容

- Docker Compose 默认映射 PostgreSQL 到 `127.0.0.1:55432`。
- Docker Compose 默认映射 Redis 到 `127.0.0.1:56379`，避开常见的宿主机 `6379` 占用。
- 支持通过 `POSTGRES_PORT`、`REDIS_PORT` 环境变量覆盖宿主端口。
- README 增加端口说明。

## 产品分析结论

- 项目需要保留，但不应成为用户开始生成前的强制门槛。
- 任务也需要保留，但它代表一次生成执行记录，不应承担长期素材和结果组织职责。
- 推荐的关系是：一个项目包含多个资产和多个生成任务；一个任务属于一个项目，但一个项目可以产生多次任务和多个结果版本。
- 当前“项目与资产”页和“任务”页确实存在心智冲突：用户会把项目理解成一次生成任务，也会把任务理解成项目容器。
- 创建项目入口应定位为“长期工作空间”，创建任务入口应定位为“本次生成操作”。两者名称、页面标题和按钮文案必须明确区分。

## 遗留问题

- 当前仍允许用户在没有项目的情况下进入工作台并生成任务，任务可能没有 `projectId`；这是为了不阻断首次体验，后续建议自动归入“未命名项目”。
- 项目创建后目前直接进入白底精修，后续应改为进入项目概览或让用户选择首个创作目标。
- 项目暂未提供重命名、归档、删除和项目级设置。
