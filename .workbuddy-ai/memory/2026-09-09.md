## 全项目代码审查（未改动代码，仅分析）

审查范围：apps/server（Go）、apps/web（Next.js 15）、packages/contracts、PRD、19 份 development-progress 记录。

### 关键发现（按严重度）

1. **电商生图名不副实**：`workbench.tsx` 的 `productAssetIds` 硬编码为 `['local-product']`，`productFile` 只存 File 从未上传；`provider.go` 的 `promptForInput` 只拼文本，完全不传输入图。白底/场景/卖点/详情四个任务实际都是纯文生图。
2. **后端零校验**：Go 端不引用 contracts，`/v1/generation/validate` 恒返回 `valid: true`，任意 JSON 可直接建任务。前端模型枚举与 `/v1/generation/capabilities` 返回值不一致（`-preview` 后缀差异，靠 `providerModelID` 兜底）。
3. **队列不可靠**：`queue.go` 单 goroutine worker，每个任务最多阻塞 5s×24 次=120s；服务重启后 processing/waiting_provider 任务永久卡死；Redis BRPop 无 ack、无死信、无重试、无并发控制。
4. **结果资产与任务脱钩**：`assets` 表无 `task_id`，生成结果与上传素材混在一起；下载失败会产生孤儿资产且无回滚。
5. **版本控制风险**：`apps/server/` 整个后端目录处于 untracked 状态（`?? apps/server/`），19 个批次的实现全部未提交。
6. 其它：无 Go 测试文件（`go test ./...` 空跑）；token 走 URL query 传参；CORS 反射任意 Origin + Allow-Credentials；migration 靠裸 `CREATE TABLE IF NOT EXISTS` 无版本管理；无计费/点数（PRD 8.8 完全未做）；首页与工作台大量硬编码假数据（credits 1280、Aero H1 项目、Unsplash 占位图）。
