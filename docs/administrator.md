# 管理员设置

后台登录地址为 `http://部署地址:端口/admin/login`。默认本机地址：<http://localhost:8080/admin/login>。

## 首次创建管理员

按 [安装说明](docker-image.md) 生成根目录 `.env` 后，用编辑器找到：

- `ADMIN_USERNAME`：默认 `admin`，可改成自己的用户名。
- `ADMIN_PASSWORD`：由 `setup` 随机生成的密码，可在首次启动前替换。

用户名使用 3–32 位小写字母、数字或下划线。密码使用 12–128 位 ASCII 长密码，不含换行。手工复制 `.env.example` 时，必须补全管理员密码和数据库密码，不能留空启动。

```sh
docker compose up -d --wait --wait-timeout 180
```

首次启动根据这两个字段自动创建独立管理员。无需先在前台注册，也无需手工修改数据库。登录时使用 `.env` 中的实际值，项目没有通用默认密码。

## 前台账号与后台管理员

| 身份       | 登录入口       | 用途                                      |
| ---------- | -------------- | ----------------------------------------- |
| 后台管理员 | `/admin/login` | 配置 AI、模型、价格、用户、公共内容和网站 |
| 普通用户   | `/login`       | 生成图片，管理本人作品、素材和提示词      |

管理员初始化不会创建前台账号、钱包或积分。需要自己使用生图功能时，请到前台 `/login` 点击“没有账号？创建账号”注册普通用户；前后台可以同名，但密码、会话和权限独立。后台“用户”列表管理的是前台账号，不会将其升级为管理员。如果前台没有“创建账号”按钮，先在后台“运营设置”中开启注册。

## 修改管理员用户名或密码

1. 用编辑器打开部署目录的根 `.env`。
2. 修改 `ADMIN_USERNAME` 或 `ADMIN_PASSWORD`，其他配置保持原值。
3. 保存后重新创建应用容器：

```sh
docker compose up -d --no-deps --force-recreate --wait --wait-timeout 180 app
```

应用按环境绑定更新同一个管理员身份，旧后台会话立即失效；使用新凭据重新登录。前台账号、素材和余额不受影响。

单纯运行 `docker compose restart app` 不会重新读取修改后的 Compose 环境变量。更改配置后使用上述 `up` 命令。

用户名不能改成另一个已存在管理员的用户名。首次把环境配置绑定到已有管理员时，需要提供其当前密码；程序不会覆盖一个无关账号的密码。

## 忘记后台密码

只要仍能访问部署目录：

1. 备份并编辑原 `.env`，为 `ADMIN_PASSWORD` 设置新密码。
2. 保持 `ADMIN_USERNAME` 和 `POSTGRES_PASSWORD` 原值。
3. 按上一节重新创建 `app`，再用新密码登录。

不要重新执行 `setup > .env` 找回管理员。这会同时替换数据库密码等安装配置，可能使已有站点无法连接数据库。

## 登录失败时检查

- 确认使用的是 `/admin/login`，而非前台登录页。
- 确认编辑的是根目录 `.env`，并已重新创建 `app`。
- 密码含 `$`、空格或 `#` 时，核对单引号及文件编码；避免复制时带入额外空白。
- 用 `docker compose ps` 检查应用和数据库健康状态；其他启动问题见 [常见问题](operations.md#常见问题)。

首次登录成功后，继续 [配置 AI 与模型](configuration.md)。
