# 模型参数与逐张交付

2026-10-22 实现，对应待办 L02、L03。自动测试和独立模拟页面的验收记录见 [测试报告](../test/reports/model-capabilities-delivery-2026-10-22.md)。

## 前台模型参数

`GET /v1/generation/capabilities` 在公开模型中返回 `capabilities.referenceImages`、`aspectRatios` 和 `resolutions`，不返回私有通道、上游地址或密钥。后台继续负责声明模型实际支持的能力，服务端仍在任务创建时校验，前台限制不能代替服务端校验。

通用生图、电商和服装表单按所选模型显示可用比例、清晰度。切换模型、应用预设或恢复历史后，原有比例、清晰度、文字和素材保持原值；不兼容时显示原因，并禁止提交。用户可明确点击替代参数按钮，或自行选择兼容模型。纯文字模型禁止添加新参考图，已有素材保留，可由用户移除；电商及服装依赖图片输入，需选择支持参考图的模型。

为兼容前后端先后更新，旧能力响应缺少 `capabilities` 时前台沿用原参数选项；后端继续作为最终校验方。新 API 始终返回模型能力。

## 逐张保存与费用

每张图片开始请求前，将位置、请求标识和模块归属写入 `generation_deliveries`，阶段依次为 `submitting`、可选的 `waiting_provider`、`saving`、`saved`；未交付记录在最终失败结算时转为 `failed`。实际通道仍保存在提交时冻结的 `generation_charges.provider_snapshot`，整组不自动切换通道。

收到单图结果后，先用现有 AI 配置加密密钥暂存图片来源，再下载并校验图片、写入对象存储。素材记录、单图保存状态、任务的 `resultImages` 和 `resultModules` 在同一数据库事务中发布。加密来源在图片保存成功或任务结算时清除，不通过用户任务 API 返回。

前台轮询处理中任务即可预览、下载已保存图片，显示真实的已保存张数；启动下一次生成时展示当前任务的结果，不混入上次图片。运行中交付图片暂时禁止删除，避免结算前被移除。全部完成后可下载整组 ZIP。

任务结束仍按冻结单价与实际入库张数结算一次。部分失败保留可交付图片，释放剩余预留；上游费用与用户积分分别计算。保存失败、下载失败或上游已收费但无可交付图片的费用由平台承担。

## 中断恢复边界

数据库每 15 秒扫描排队及租约过期任务，统一进入现有 Worker 容量。领取使用行锁和独立租约令牌；租约 2 分钟，每 30 秒续期。逐张状态、资产发布和结算都校验当前令牌及未过期租约，旧 Worker 返回的迟到响应不能覆盖新处理结果。

恢复时依据持久化阶段处理：

| 已记录状态 | 处理方式 |
| --- | --- |
| 全部图片已保存，尚未结算 | 直接结算，不再读取上游服务或提交请求 |
| 单图已保存 | 复用原资产和模块归属，不重复保存 |
| 已收到结果且加密来源可读 | 从记录的来源完成保存，不重新生图 |
| 已有供应商任务 ID，且适配器明确声明支持恢复 | 只查询原任务，不重复提交生成请求 |
| 同步请求中断，结果尚未记录 | 保留已有图片，结束任务并退回剩余预留；提示重新生成会创建新任务并计费 |
| 升级前无逐张记录的处理中任务 | 仅按已有可交付资产结算，不重放旧请求 |

当前后台可配置的 `openai_images`、`openai_chat`、`gemini_native` 均为同步协议，拒绝仅返回远程任务 ID 的响应。可恢复查询的接口分支由模拟 Provider 验证，本次没有增加真实异步协议、任意轮询地址或自动重试生成。同步上游未被本服务收到并记下的结果，无法靠刷新页面补回。

浏览器丢失创建响应时，继续使用原提交编号核对原任务；若核对时任务已完成，直接恢复结果。用户主动再次生成属于新任务，独立预留并结算。

## 升级与运行

新增迁移 `012_generation_delivery.sql`，增加任务租约令牌和逐张交付表。沿用文件迁移记录，重复启动不会重复执行已应用迁移。升级前按现有流程备份 PostgreSQL、对象存储和 AI 加密密钥；密钥同时用于读取尚未保存完成的临时结果。

本轮只修改源码并在独立测试数据库与模拟预览中验收，没有升级当前运行中的业务容器。部署仍按单 API 进程边界执行；多副本的共享存储、密钥及部署行为需要单独验收。
