# 注册赠送、签到与积分获取

2026-10-22 完成 L21 注册赠送专项验收、L22 每日签到、L13 积分获取路径，并增加网站公告。验收证据见 [专项报告](../test/reports/credits-prompt-acceptance-2026-10-22.md)。

## 后台配置

入口：**运营设置**。沿用管理员权限、配置事务与操作日志。

| 区域           | 配置                               | 行为                                                       |
| -------------- | ---------------------------------- | ---------------------------------------------------------- |
| 账户与注册     | 注册赠送数量                       | 最多两位小数；0 不赠送，只影响之后成功注册的新账号         |
| 平台额度与告警 | 每日注册赠送总预算                 | 延续 L04：不足以全额赠送时暂停新注册，已有账号不受影响     |
| 签到与积分获取 | 开启每日签到奖励、每次签到赠送数量 | 初始关闭、单次奖励为 0；开启且数量大于 0 才可领取          |
| 签到与积分获取 | 每日签到赠送总预算                 | 默认 1000 积分；0 或剩余预算不足时暂停当天的新领取         |
| 签到与积分获取 | 积分补充说明、积分联系入口         | 联系入口初始留空；支持 http/https 网页或纯 mailto 邮箱链接 |
| 网站公告       | 发布公告、标题、正文               | 初始关闭；发布时标题和正文必填，分别最多 60、2000 字       |

数量在 API、数据库和流水中以整数最小单位保存，100 个最小单位等于 1 积分。单次注册、签到奖励上限均为 100 万积分。签到总预算上限为 100 亿积分。前台仍使用后台设置的积分名称。

联系入口不接受脚本协议、带账号密码的 URL 或附加邮件收件参数。它仅提供联系地址，前台不会自动发送邮件或代用户申请。首版仍由管理员在「用户与余额」人工发放，未接入在线支付、套餐、订单或自动充值。

## 签到规则与一致性

- 仅正常状态的前台登录账号可以主动领取。管理员会话不能代替用户领取，客户端提交的账号、日期和金额不参与发放决策。
- 按数据库提供的 `Asia/Shanghai` 自然日判断，每账号每天一次，次日 00:00 更新。不依赖浏览器时间或应用进程时区。
- 修改奖励只影响之后的首次领取；已领取金额按原记录显示。当天关闭后重开、刷新、重新登录或进程重启均不会补发。
- 签到记录、可用余额增加和「签到奖励」流水在同一事务中提交，任何一步失败全部回滚。
- 用户与钱包行锁、`(user_id, claim_day)` 唯一键和数据库事务级预算锁共同约束并发领取，预算跨用户、跨 API 进程共享。预算用尽后，已成功领取的请求重试仍返回原奖励。
- 未实现连续签到、补签、奖励阶梯或自动发放。每日总预算限制赠送总量，不等同于完整的多账号反滥用系统。

接口：

| 接口                         | 用途                                                                   |
| ---------------------------- | ---------------------------------------------------------------------- |
| `GET /v1/operation-settings` | 公开注册赠送、有效签到开关和奖励、已发布公告；不公开内部预算或联系配置 |
| `GET /v1/account`            | 登录用户的余额、流水及 `creditPolicy`（注册规则、联系入口、签到状态）  |
| `GET /v1/account/checkin`    | 登录用户当日签到状态                                                   |
| `POST /v1/account/checkin`   | 主动领取，返回 `checkin`、`availableMinor`、`heldMinor`；不需要请求体  |

签到状态包含 `date`、`nextClaimAt`、`refreshAfterSeconds`、`rewardMinor`、`claimedRewardMinor`、`claimed`、`canClaim` 和预算不足原因。已领取时以 `claimedRewardMinor` 为凭据，而非当前配置金额。

## 用户流程

注册页展示当前赠送规则；个人中心新增「获取积分」，展示签到、人工补充入口、当前用户名、注册规则及计费退款说明。未配置联系入口时明确显示状态，不生成空链接。

工作台显示模型单价、张数和预计预留。余额不足时，「获取积分」在新窗口打开个人中心，原窗口继续保留描述与已选素材。领取成功后广播无身份信息的版本标记，其他窗口重新读取余额及报价；窗口重新获得焦点时也会刷新。标记不携带用户标识、余额或访问令牌。

签到按钮限制单次在途请求。响应丢失后先重新读取账户再允许重试，服务端幂等约束提供最终保障。页面按服务端返回的剩余秒数跨日刷新，并在切回窗口时核对状态，没有后台持续轮询任务。

生成继续按所选模型单价乘张数预留，完成后按实际交付结算，未交付部分退回。提示词优化、图片反推与服装分析不另扣积分，受已有辅助次数和平台额度约束；这不代表上游服务没有实际成本。

## 网站公告

首版是一条当前公告，纯文本显示并保留换行，不执行 HTML。前台首次看到某个内容版本时弹出，关闭后在本机记录内容摘要；浮动「公告」入口可再次查看。标题或正文变化后，下一次页面加载会重新提示；相同内容重新启用不会强制重复提醒。后台管理页面不显示前台公告。

公告按前台区域挂载时读取一次，没有定时轮询、实时推送、排期、多条历史或置顶列表。关闭发布后，新的页面加载不再返回公告；已经打开的页面在重新加载后同步。公告只承担运营通知，不能代替用户同意或正式条款。

## 升级与启用

新增迁移 `016_daily_checkins.sql`，由项目现有数据库迁移机制随 API 版本升级应用。本轮只对隔离数据库执行迁移和验收，未迁移业务库或重建业务容器。

升级后先在后台填写真实的联系入口，确认注册赠送和预算，再按试运营计划开启签到、设置单次奖励及总预算，最后填写并发布公告。验收截图中的用户名、奖励、联系网址及公告均为隔离测试数据，不是业务环境默认配置。
