# AI 电商创作平台 PRD（MVP）

> 文档版本：v1.1  
> 文档日期：2026-09-07  
> 产品阶段：MVP / 开发交付稿  
> 参考产品：三万图 AI 工作台、[PixPix](https://www.pixpix.com/zh-CN)（仅用于分析产品模式，不照搬品牌、素材与实现）

## 1. 文档说明

### 1.1 已知条件

- 产品定位：面向电商经营者与设计人员的 AI 图片创作平台。
- MVP 核心：AI 通用生图、AI 电商图生成。
- 前台只呈现“通用生图”和“电商工具”两种模式；两种模式共用统一生图模型路由，但采用相互独立的生成参数结构。
- 后续方向：无限画布、批量生产、SKU 套图、局部编辑与团队协作。
- 开发要求：采用主流技术栈和成熟 UI 框架，优先保证可交付、可扩展和模型可替换。

### 1.2 默认假设

- 首发同时服务国内中小商家和跨境电商团队，Web 桌面端优先，产品界面语言为简体中文。
- 首批用户覆盖淘宝、天猫、京东、拼多多、抖音、小红书、Amazon 和 Shopify/独立站商家。
- MVP 不训练自有基础模型，以第三方生图模型 API 为主，平台负责工作流、提示词编排、商品一致性、任务调度和资产管理。
- 商业模式采用点数制；支付、企业席位、开放 API 在 MVP 后逐步完善。
- 移动端仅保证浏览、查看任务和下载，不承诺完整创作体验。

## 2. 产品概述

### 2.1 产品愿景

让没有专业设计能力的电商用户，也能用商品原图和一句需求，在几分钟内得到可上架、可投放、可继续编辑的商品视觉素材。

### 2.2 用户问题

当前电商图片生产通常存在以下问题：

1. 传统设计链路慢，拍摄、修图、排版与多轮沟通成本高。
2. 通用生图工具不理解电商平台规格、商品一致性和广告合规。
3. 同一商品需要白底图、场景图、卖点图、详情页等多种素材，重复劳动严重。
4. 不同模型使用方式不一致，提示词、参数和历史素材散落，难以复用。
5. AI 结果不可控，常见问题包括商品变形、Logo 和文字错误、颜色偏差及背景穿帮。

### 2.3 核心价值主张

- 快：上传商品图后，3 分钟左右生成一组候选素材。
- 懂电商：内置平台尺寸、商品图类型、卖点结构与合规约束。
- 可控：支持参考图、风格、比例、数量、负向约束和重新生成。
- 可复用：提示词模板、项目和资产统一沉淀。
- 可扩展：同一项目与任务底座后续承载无限画布和批量工作流。

### 2.4 北极星指标

**每周成功导出的电商图片数（Weekly Successful Exported Commerce Images）**。

“成功导出”定义：生成完成后，用户预览并主动下载或加入项目资产的图片；同一图片重复下载只计一次。

## 3. 目标与范围

### 3.1 MVP 目标

- 用户可从注册到完成首次生图，形成端到端闭环。
- 支持通用 AI 生图及以商品原图为核心的电商图生成。
- 生成过程异步、可恢复、可追踪，刷新页面不丢任务。
- 用户可管理生成历史、上传素材和下载结果。
- 平台可配置模型、计费规则、提示词模板和风险词。

### 3.2 成功指标（上线后 30 天）

| 指标 | 目标 |
|---|---:|
| 注册用户首次生成完成率 | >= 65% |
| 首次成功生成耗时 P50 | <= 180 秒 |
| 生成任务成功率 | >= 95% |
| 生成结果导出率 | >= 35% |
| 7 日创作留存率 | >= 20% |
| 商品主体严重变形投诉率 | <= 5% |
| 单张生成综合毛利率 | >= 40% |

### 3.3 MVP 范围（P0）

- 手机号或邮箱登录/注册。
- 工作台与模式切换。
- 任务首页：按创作目标进入聚焦编辑器，并展示输入要求和预期交付物。
- 通用 AI 生图：文生图、图生图。
- AI 电商图：白底图、场景图、卖点主图、详情页单页素材。
- 商品图上传、参考图上传、提示词输入与智能优化。
- 比例、分辨率、数量、模型和风格配置。
- 异步生成、进度显示、失败重试和点数退回。
- 结果预览、基础裁剪/平台尺寸适配、单张下载、批量下载、再次生成、创建变体。
- 生成结果在当前任务内预览、裁剪和下载。
- 项目历史、资产中心、收藏和删除。
- 点数余额、消耗明细和基础套餐展示。
- 内容安全、广告法风险词提醒、用户协议和隐私说明。
- 基础运营后台。

### 3.4 暂不纳入 MVP

- 无限画布与多人实时协作。
- 视频生成、3D 商品图、数字人。
- PSD/Figma 分层文件导出。
- 完整详情页长图自动排版与在线富文本编辑。
- 智能商品套图编排、生成式局部重绘、扩图、改变视角和一键高清放大。
- 批量 SKU 自动跑批、Excel 导入和开放 API。
- 自训练模型、LoRA 训练和企业专属模型。
- 复杂团队权限、品牌资产审批和私有化部署。

## 4. 用户与场景

### 4.1 核心用户

| 用户 | 主要任务 | 痛点 | MVP 价值 |
|---|---|---|---|
| 中小商家/店主 | 快速上新、活动换图 | 预算有限、不会设计 | 模板化生成可直接使用的商品图 |
| 电商运营 | 制作主图、测款素材 | 需求多、迭代快 | 一次生成多种方向并快速下载 |
| 电商设计师 | 找创意、做初稿与延展 | 重复修图多 | 保持商品一致性的批量草案 |
| 代运营/跨境电商团队 | 多客户、多站点、多语言商品交付 | 资产混乱、成本难核算、平台规格不同 | 按项目沉淀素材和生成记录，按目标市场输出文案 |

### 4.2 关键使用场景

1. 新商品只有手机拍摄图，需要生成干净白底主图。
2. 运营需要为同一商品生成 3 种场景风格，用于 A/B 测试。
3. 店主输入产品卖点，生成带信息区但不过度承诺的卖点主图。
4. 设计师上传竞品参考图，只借鉴构图与氛围，不替换自己的商品。
5. 用户对某张结果满意，希望保留商品和风格继续生成变体。

## 5. 产品原则

1. **商品优先**：商品外观、材质、颜色、Logo 和关键结构优先于画面风格。
2. **先选择目标，再配置参数**：用户先选“要做什么图”，系统再展示必要参数。
3. **结果可追溯**：每张图都能回看输入素材、提示词、模型、参数和费用。
4. **失败可恢复**：任务可重试，失败不重复扣费，页面刷新不丢状态。
5. **默认值可用**：新用户不理解模型参数也能生成，专业设置渐进披露。
6. **不承诺完全自动上架**：生成结果应提示用户检查商品真实性、文字和平台规则。

## 7. 核心用户流程

### 7.1 首次通用生图

```text
进入工作台 → 选择“通用生图” → 输入描述
→ 可选上传参考图 → 选择比例/数量/风格
→ 系统预估点数 → 点击生成 → 查看进度
→ 预览结果 → 下载/收藏/创建变体
```

### 7.2 首次电商图生成

```text
进入工作台 → 选择“电商图” → 选择创作目标
→ 上传 1~10 张商品图 → 可选参考图
→ 填写商品名称、卖点和补充要求
→ 选择平台/比例/数量/风格 → AI 优化需求
→ 确认预估点数 → 提交任务
→ 商品分析 → 生成图片 → 查看与筛选
→ 下载/收藏/创建变体/重新生成
```

### 7.3 异常流程

- 上传失败：保留已成功文件，支持单文件重试。
- 余额不足：不创建任务，展示差额和套餐入口。
- 模型超时：任务自动重试最多 2 次；仍失败则退回点数。
- 部分图片失败：成功结果即时可用，只退回失败部分点数。
- 安全审核拦截：不调用模型、不扣点，指出需要修改的内容类型。
- 页面关闭：任务继续执行，用户可在项目/通知中恢复查看。

## 8. 功能需求

### 8.1 账号与新手引导

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| AUTH-01 | 手机验证码或邮箱验证码登录 | P0 | 验证成功后创建/进入账户；验证码有频率限制 |
| AUTH-02 | 同意协议 | P0 | 首次注册必须主动勾选用户协议与隐私政策 |
| AUTH-03 | 新用户赠送体验点数 | P0 | 赠送记录可在明细查询，规则后台可配置 |

| AUTH-05 | 游客浏览 | P0 | 未登录用户可查看任务入口、示例交付物和模板；上传自有素材或提交生成前要求登录，登录后保留当前配置 |

### 8.2 工作台通用结构

任务首页只呈现两种生图模式。通用生图首页直接展示描述输入框、模型和画面设置；点击顶部“AI 图片”、提交描述或添加参考图后进入统一生成工作台的“通用”。点击顶部“电商工具”直接进入同一工作台的“商品 / 白底精修”，首页电商工具区仍展示白底精修、商品场景图、卖点主图和详情页单页四个入口。旧版独立通用生图编辑器弃用。统一工作台左侧一级菜单固定为“通用 / 商品”，商品模式的四类任务放在顶部二级栏。首页工具区下方保留最近项目与发现灵感列表。两种模式共用统一模型路由，但前端参数 schema 独立：通用模式使用描述、参考图、风格、参考强度、比例、清晰度和数量；商品模式增加商品原图、平台、语言、卖点、内容模块和视觉方向。桌面编辑器采用固定参数面板 + 结果画布，提交前展示预期结果，提交后切换为任务状态和结果。

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| WB-01 | 模式切换 | P0 | 顶部生图入口只有“AI 图片/电商工具”两个；统一工作台左侧提供“通用/商品”一级切换，商品模式才显示四类商品任务标签；发现灵感、项目和资产为支持模块，不计为生图模式 |
| WB-02 | 参数草稿自动保存 | P0 | 登录用户 2 秒防抖保存；刷新后恢复最近草稿 |
| WB-03 | 费用预估 | P0 | 参数变化后 500ms 内更新预计消耗，提交前再次以后端报价为准 |
| WB-04 | 示例任务 | P1 | 无素材时可使用平台示例体验，但结果标记为示例衍生 |
| WB-05 | 响应式布局 | P0 | >=768px 结果画布 + 参数面板双栏；<768px 单栏分步操作 |
| WB-06 | 任务入口 | P0 | 首屏按用户任务而非底层模型展示入口；点击后进入对应聚焦编辑器，不先要求理解模型差异 |
| WB-07 | 示例交付物 | P0 | 每个任务入口展示至少 1 组“输入素材 → 输出结果”和输出类型说明；示例不得冒充用户真实生成结果 |
| WB-08 | 最近任务恢复 | P0 | 项目/创作积累页显示最近任务及状态，点击可继续查看结果或恢复未提交草稿 |
| WB-09 | 配置面板位置偏好 | P1 | 桌面端在“生成配置”标题栏提供左侧/右侧两项图标切换，默认左侧；选择在通用生图与商品生图间共享并持久化。该设置只改变工作区布局，不影响生成参数；移动端隐藏入口并固定为画布在上、配置在下 |

### 8.4 AI 电商图生成

#### 8.4.1 创作目标

| 类型 | 输入要求 | 默认输出 | 可选数量 | 主要约束 |
|---|---|---|---|---|
| 白底图 | 至少 1 张商品图 | 1 张 1:1 | 1~4 张 | 纯白背景、自然阴影、商品不变形 |
| 场景图 | 商品图，可选参考图 | 1 张 1:1 | 1~4 张 | 场景合理、接触关系自然、不遮挡主体 |
| 卖点主图 | 商品图 + 至少 1 条卖点 | 1 张 1:1 | 1~4 张 | 生成无字底图并提供可复制的文案建议，画面预留信息区 |
| 详情页单页 | 商品图 + 内容主题 | 1 张 3:4 | 1~4 张 | 单页单主题，如材质、细节、使用场景 |

#### 8.4.2 商品素材

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| EC-01 | 商品图上传 | P0 | 单次 1~10 张；JPG/PNG/WebP；单张 <=20MB；短边 >=512px |
| EC-02 | 主参考图指定 | P0 | 多图时必须有 1 张主图，默认第一张，可拖动排序 |
| EC-03 | 基础质量检查 | P0 | 检查分辨率、格式和损坏文件；低质量时给出非阻塞提示 |
| EC-04 | 商品抠图 | P0 | 后端生成主体蒙版，用于白底与场景合成；失败时允许继续使用原图模式 |
| EC-05 | 对标参考图 | P0 | 最多 4 张，仅参考构图/风格；界面明确不复制品牌与具体文案 |

| EC-16 | 智能商品套图 | P1 | 系统按类目和上架平台推荐套图结构；用户可在智能匹配和自定义结构间切换，并逐项选择图片类型与数量 |

#### 8.4.4 商品分析

提交后，系统先通过视觉模型提取结构化商品信息：

- 商品类目、主体数量、主要颜色、材质、形状与关键结构。
- Logo、包装文字、不可改变区域。
- 原图背景、拍摄角度、遮挡和质量问题。
- 适配场景、建议构图和风险点。

分析结果用于提示词编排和结果质检。MVP 中分析过程与生成任务合并展示，不增加必须确认的中间步骤；用户可在结果详情查看报告。

### 8.5 任务与结果

任务状态机：

```text
DRAFT → QUOTED → QUEUED → ANALYZING → GENERATING
      → SUCCEEDED / PARTIAL_SUCCESS / FAILED / CANCELED
```

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| TASK-01 | 异步任务 | P0 | 提交后 1 秒内返回任务 ID；刷新或更换设备可继续查看 |
| TASK-02 | 进度反馈 | P0 | 展示排队、分析、生成、完成阶段；无法获得真实百分比时不伪造精确进度 |
| TASK-03 | 幂等提交 | P0 | 网络重试不会创建重复任务或重复扣点 |
| TASK-04 | 失败重试 | P0 | 系统最多自动重试 2 次；用户可手动重试失败图片 |
| TASK-05 | 结果网格 | P0 | 支持单图预览、选择、收藏、下载、删除和查看详情 |
| TASK-06 | 创建变体 | P0 | 沿用选中图片及原参数，可修改提示词和参考强度 |
| TASK-07 | 重新生成 | P0 | 使用原始参数创建新任务，提交前显示本次价格 |
| TASK-08 | 下载 | P0 | 单图 PNG/JPG 下载；多选后 ZIP 下载；保留原始分辨率 |
| TASK-09 | 结果元数据 | P0 | 记录模型、版本、种子、提示词、尺寸、输入素材、时间和费用 |
| TASK-10 | 基础裁剪与尺寸适配 | P0 | 结果可按目标平台预设比例裁剪并导出；保留原始结果，不覆盖源文件；该操作不额外调用生成模型 |
| TASK-11 | 快捷生成式编辑 | P1 | 结果可进入局部重绘、局部消除、扩图、改变视角、移除背景和高清放大；每次操作生成新的派生资产并单独报价 |

### 8.6 项目与资产中心

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| ASSET-01 | 自动项目 | P0 | 首次生成时自动创建项目，名称默认为“商品名 + 日期” |
| ASSET-02 | 项目管理 | P0 | 支持重命名、封面、归档和删除；删除进入 7 天回收期 |
| ASSET-03 | 资产分类 | P0 | 区分上传素材、生成结果、收藏；支持类型和时间筛选 |
| ASSET-04 | 资产复用 | P0 | 可从资产中心将已有图片加入新任务或标记为参考素材，无需重复上传；派生结果保留来源关系 |
| ASSET-05 | 存储期限 | P0 | 套餐页和资产页显示存储规则；到期前提醒用户下载 |

### 8.7 提示词与模板

- 系统模板按白底、主图、场景、详情、风格、合规分类。
- 模板可“插入”到现有描述或“替换”当前描述。
- 用户可收藏模板；自定义模板为 P1。
- 系统提示词由服务端维护并版本化，不直接暴露内部编排内容。
- 模板升级不影响历史任务复现，任务保存实际使用的模板版本和最终参数。
- P1 增加“发现灵感”和“一键同款”：用户选择公开示例后，仅复用其可公开的构图/风格模板，不泄露原作者提示词或输入素材。

### 8.8 点数与计费

#### 计费原则

- 任务提交前由服务端生成报价单 `quote_id`，有效期 10 分钟。
- 提交时预冻结点数；单张成功后结算，失败部分自动解冻。
- 不同模型、分辨率、数量和工作流可配置不同单价。
- AI 提示词优化和商品分析可并入生成价，减少用户理解成本。

#### MVP 页面

- 当前余额。
- 本次预计消耗及计价明细。
- 点数流水：赠送、购买、冻结、消耗、退回、过期。
- 套餐展示；支付未接入时可使用联系客服或兑换码作为内测方案。

### 8.9 通知

- 站内通知：任务完成、部分失败、全部失败、点数退回。
- 页面内 Toast 只反馈即时操作，不承担长任务完成通知。
- 从顶部导航触发的通知反馈显示在导航下方的页面顶部，不使用底部 Toast 位置。
- 浏览器通知需用户主动授权，作为 P1。

### 8.10 运营管理后台

| 模块 | MVP 能力 |
|---|---|
| 用户 | 查询、封禁/解封、点数调整、任务查看 |
| 模型 | 供应商启停、模型路由、单价、超时和并发配置 |
| 模板 | 模板增删改、分类、上下线、版本管理 |
| 内容安全 | 风险词、拦截原因、申诉记录、审核日志 |
| 任务 | 状态查询、失败原因、重试、成本和耗时 |
| 运营数据 | 注册、活跃、任务量、成功率、导出率、模型成本 |

所有后台敏感操作写入不可修改的审计日志。

### 9.1 工作台页面

├─────────────────────────────────────────────────────────────┤
│                   通用生图描述输入框                         │

首页默认服务通用生图；电商图从电商创作工具进入。发现灵感、项目和资产是创作支持模块，不属于新的生图模式。任务卡必须显示名称、输入要求、示例结果和默认输出，不展示底层技术说明。

#### 9.1.2 统一生成工作台

┌────────┬─────────────────────────────────────────────────────┐

### 9.2 关键交互规则

- 主按钮使用“生成 + 当前任务名”；加载状态不可改变按钮宽度。具体点数单价未确认前，不在按钮中硬编码报价。
- 统一工作台左侧固定展示“通用 / 商品”；通用模式不显示商品任务标签，商品模式可切换相邻商品任务且不得清空草稿。
- 通用生图画布使用纯白背景并放大结果图片，参数区与商品模式一致使用独立圆角面板。
- 比例使用带缩略框的单选卡；颜色选择使用色板；数量使用步进器。
- 模型选择放入高级设置，默认使用平台推荐模型，避免新用户决策负担。
- 上传区支持点击、拖拽、粘贴；上传后显示缩略图、进度、失败状态和删除按钮。
- 电商模式上传对标图后，以可取消的标签展示“构图、色彩、材质、光影、风格、氛围”视觉拆解结果；通用生图不展示该模块。
- 生成中允许继续编辑新草稿，不阻塞整个工作台。
- 图片详情采用全屏灯箱，支持左右切换、缩放、对比输入图和下载。
- 结果区的一级操作仅保留下载、裁剪/尺寸适配、创建变体；生成式编辑收进“更多编辑”，避免工具条堆满。
- 高风险操作如永久删除必须二次确认；普通参数切换不弹确认框。
- 所有图标按钮提供 Tooltip、焦点态和可访问名称。

### 9.3 视觉与组件规范

建议采用 **shadcn/ui + Tailwind CSS**。shadcn/ui 提供基于 Radix UI 的可访问组件源码，便于工作台按业务需要深度定制；Tailwind CSS 负责设计令牌、布局和组件样式。表单、上传、数据表格和通知分别配合 React Hook Form、Dropzone、TanStack Table 与 Sonner 实现。组件统一收敛在 Monorepo 的 `packages/ui` 中，避免页面自行复制组件。

基础规范：

- 首页、导航与主工作区使用 `#FFFFFF`；电商工具弹窗外层可使用中性浅灰 `#ECECEA`；正文使用 `#171717`。
- 界面采用黑、白与中性灰，不设置彩色品牌主色；商品素材和生成结果承担页面色彩。
- 状态同时使用文字、图标、明度和边框表达，不只依赖颜色。
- 字号：10/11/12/13/14/16/18/20/29/42px；工作台正文和表单默认 13~14px，可交互文字不得小于 10px。
- 间距使用 4px 基准；卡片圆角 6~8px；控件高度 32/40px。
- 信息密度偏工作型工具，不使用大面积营销 Hero 和装饰性渐变。
- 任务首页使用真实、清晰的输入/输出案例作为主要视觉信号；编辑器保持克制，将视觉面积优先留给商品和结果，不使用与任务无关的氛围图。
- 统一生成工作台采用“配置 + 结果”并行结构，配置默认左侧并允许用户换到右侧；通用与商品模式共享页面壳层，但使用独立参数表单，避免形成一个过度复杂的通用表单。
- 正文和背景对比度达到 WCAG 2.2 AA；键盘焦点可见。

### 9.4 页面状态清单

每个页面必须覆盖：加载、空数据、正常、局部失败、无权限、网络断开和系统维护状态。工作台额外覆盖上传中、余额不足、排队、分析、生成、部分成功和安全拦截状态。

## 10. AI 工作流设计

### 10.1 通用生图链路

```text
用户输入
→ 内容安全预检
→ 提示词优化（可选）
→ 模型路由与参数标准化
→ 生成供应商
→ 输出安全审核
→ 文件持久化
→ 结果入库与计费结算
```

### 10.2 电商图链路

```text
商品图上传
→ 图片质量检测/抠图
→ 多模态商品分析
→ 商品约束 JSON
→ 根据创作目标选择工作流模板
→ 合并用户要求与合规规则
→ 模型路由（图生图/局部重绘/背景生成）
→ 输出审核与商品一致性评分
→ 持久化、结算与结果展示
```

### 10.3 商品约束结构示例

```json
{
  "category": "头戴式耳机",
  "identity": {
    "primaryColor": "黑色",
    "materials": ["哑光塑料", "金属转轴"],
    "mustKeep": ["椭圆耳罩", "头梁比例", "侧面品牌标识"],
    "forbiddenChanges": ["颜色", "Logo 内容", "接口数量"]
  },
  "composition": {
    "preferredAngles": ["正面 45 度", "侧面"],
    "safeTextAreas": ["右上", "右侧"]
  },
  "risks": ["黑色主体与深背景易融合", "品牌文字可能失真"]
}
```

### 10.4 模型路由策略

- 业务代码不直接耦合 BananaRouter 的具体模型，通过统一 `ModelProvider` 接口访问。
- 路由输入：任务类型、所需分辨率、参考图数量、质量档位、供应商健康度、预计成本。
- MVP 至少接入 1 个主模型和 1 个备用模型；主模型不可用时只对兼容任务自动降级。
- 供应商原始请求和响应需脱敏记录，图片 URL 不长期依赖供应商临时地址。
- 每个任务记录实际模型、模型版本和供应商任务 ID，便于对账和排障。

### 10.5 输出质检

MVP 采用“自动评分 + 用户提示”，暂不因低分自动无限重跑：

- 安全与违规内容：必须通过，否则拦截。
- 图像完整性：文件可解码、尺寸正确、无纯黑/纯白异常图。
- 商品一致性：通过视觉模型对比颜色、结构、Logo 区域和主体数量。
- 文字风险：OCR 检测乱码、绝对化用语和不可验证声明。
- 低于阈值时标记“建议检查”，允许用户手动重试并收集反馈。

### 11.1 推荐技术栈

| 层级 | 选型 | 说明 |
|---|---|---|
| Web 前端 | Next.js 15+、React 19、TypeScript | 生态成熟，支持 SSR、路由、鉴权和后续官网 SEO |

| API 服务 | NestJS、Node.js LTS、TypeScript | 模块化、DI、OpenAPI 与队列生态适合 SaaS MVP |
| 数据库 | PostgreSQL 17+、Prisma ORM | 事务可靠，JSONB 适合模型参数，迁移工具成熟 |
| 缓存/队列 | Redis 7+、BullMQ | 任务队列、限流、缓存、分布式锁 |

### 11.6 关键工程策略

- 前端直传对象存储，服务端签发短时上传凭证；上传完成后服务端校验文件。
- 原图和结果图使用私有 Bucket，默认通过短时签名 URL 访问。
- Worker 使用任务租约和心跳，避免进程退出后任务永久卡死。
- 外部模型调用设置连接/响应超时、指数退避、熔断和供应商级并发上限。
- Webhook 与主动轮询并存，所有供应商回调必须验签且幂等。
- ZIP 下载异步打包并设置过期时间，避免 API 进程占用大量内存。
- Prompt、模型路由和价格规则全部版本化，可灰度发布和回滚。

## 12. 非功能需求

### 12.1 性能与可用性

| 项目 | 目标 |
|---|---:|
| 页面首屏 LCP（国内主流网络） | <= 2.5 秒 |
| 常规 API P95 | <= 500ms |
| 创建任务 API P95 | <= 1 秒 |
| 上传成功率 | >= 99% |
| 月度服务可用性 | >= 99.9% |
| SSE 断线恢复 | 30 秒内自动恢复并补拉状态 |

### 12.2 安全与隐私

- 全链路 HTTPS；密码使用 Argon2id；验证码和登录接口限流。
- 对象存储私有化、URL 短时签名、服务端校验 MIME 与文件头。
- 图片 EXIF 默认移除，避免泄露地理位置和设备信息。
- 防范 SSRF、恶意文件、越权访问、重复扣费和回调伪造。
- 用户可删除项目和资产；后台任务在回收期后物理删除原图、缩略图和结果图。
- 明确告知第三方模型处理范围、数据保存期限及是否用于模型训练。
- 日志不得记录验证码、Token、完整手机号、完整提示词中的敏感信息或永久图片 URL。

### 12.3 内容与版权治理

- 输入输出均接入涉政、色情、暴力、仇恨、未成年人等安全审核。
- 禁止生成仿冒品牌、侵权角色、虚假证书和误导性医疗功效素材。
- 对参考图明确提示用户需拥有使用权；保留任务与审核记录以处理投诉。
- 生成图下载页提供“AI 生成内容，请人工核验”的提示；MVP 暂不实现水印和内容凭证，后续根据法规与商业方案另行评估。
- 合规策略必须由法务在上线前复核，本 PRD 不构成法律意见。

### 12.4 可访问性

- 支持键盘完成核心工作流。
- 图片提供可配置替代文本；上传和生成状态通过文本而非只用颜色表达。
- 表单错误与对应字段关联；焦点不被抽屉、弹窗或 Toast 吞掉。
- 关键文本对比度达到 WCAG 2.2 AA。

## 14. 验收标准

### 14.1 核心 Happy Path

1. 新用户在未登录状态浏览任务入口和示例，选择白底图后进入聚焦编辑器。
2. 用户登录并获得体验点数，当前任务配置继续保留，然后上传合法商品图。
3. 系统完成上传、质量检查并给出点数报价。
4. 用户提交后立即获得任务 ID，任务进入队列且只冻结一次点数。
5. 页面实时显示分析、生成和完成状态。
6. 至少一张成功结果可预览、下载、收藏并用于创建变体。
7. 项目与资产中心可查询完整输入、参数、结果和点数流水。

### 14.2 必测错误场景

- 非法格式、超大文件、低分辨率、损坏图片。
- 快速双击提交、网络超时后重试、重复 Webhook。
- 点数不足、报价过期、生成中余额发生变化。
- 主模型限流、超时、返回空图、返回违规图。
- 部分成功、自动重试失败、任务进程重启。
- 用户 A 访问用户 B 的项目、图片和签名 URL。
- 删除项目后恢复、回收期后物理删除。

### 14.3 发布门槛

- P0 功能验收全部通过，无阻塞级和严重级缺陷。
- 核心接口完成鉴权、幂等、限流和越权测试。
- 任务成功率压测达到 95%，队列积压和熔断告警可用。
- 钱包对账结果为零差异，失败任务点数可完整退回。
- 隐私政策、用户协议、模型供应商条款及内容治理方案完成审核。

## 15. 研发计划

建议配置：1 产品、1 UI/UX、2 前端、2 后端、1 AI 应用工程师、1 QA，采用 2 周 Sprint。

| 阶段 | 周期 | 交付 |
|---|---:|---|
| Sprint 0 | 1 周 | 技术验证、模型选型、成本测算、原型与数据模型 |
| Sprint 1 | 2 周 | 账号、任务首页、工作台骨架、上传、项目与资产基础 |
| Sprint 2 | 2 周 | 通用生图、任务队列、SSE、结果预览、基础裁剪与下载 |
| Sprint 3 | 2 周 | 电商图工作流、商品/参考图分析、详情模块、抠图与提示词编排 |
| Sprint 4 | 2 周 | 钱包计费、后台、安全审核、埋点与错误恢复 |
| Beta | 1~2 周 | 小流量内测、质量调优、成本与并发压测 |

预计 MVP 为 10~11 周。若团队只有 3~4 名研发，建议将管理后台、自定义模板和 2K 输出降为 P1，周期调整为 12~14 周。

## 16. 版本路线

### V1.1：生产效率

- 智能商品套图：按平台和品类自动匹配结构，也支持自定义图片类型与数量。
- 完整详情页/A+ 套图：按首屏主视觉、核心卖点、场景、多角度、规格等模块批量生成。
- 结果快捷编辑：局部重绘、扩图、局部消除、移除背景、改变视角和高清放大。
- SKU 替换、批处理、Excel 导入。
- 自定义提示词模板、品牌色和品牌资产。
- 文字图层后置渲染，支持编辑字体、字号、颜色和位置。
- 更多平台尺寸和一键压缩导出。

### V1.2：无限画布

- 项目进入可缩放无限画布，节点类型包括输入图、提示词、生成结果、文本和分组。
- 从任意结果创建分支，支持局部重绘、扩图、抠图、擦除和替换背景。
- 画布自动保存、版本历史、撤销/重做和导出选区。
- 初期单人编辑；多人光标、评论和权限后置。

无限画布建议采用 `tldraw` 或 `React Flow + Konva/Fabric.js` 组合评估后选型。若目标是自由排版和图像编辑，优先 tldraw；若目标是节点式 AI 工作流，优先 React Flow。不要在需求未验证前同时实现两套交互范式。

### V2：团队与生态

- 团队空间、角色权限、共享资产和审批。
- 开放 API、Webhook、Shopify/店铺 ERP 连接器。
- 企业品牌模型、专属工作流和成本中心。
- 视频生成、数字人和跨媒体营销素材。

## 17. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 商品一致性不稳定 | 结果不可商用、投诉增加 | 商品约束、抠图/合成优先、多图参考、质量评分与问题反馈 |
| 中文文字乱码 | 卖点图不可用 | MVP 以留白和文案建议为主；V1.1 采用后置文本图层 |
| 模型供应商不稳定 | 任务失败、交付延迟 | 统一适配层、备用模型、熔断、重试和容量告警 |
| 单张成本失控 | 毛利下降 | 提交前报价、分辨率分档、成本监控、缓存与供应商路由 |
| 任务状态错乱/重复扣费 | 资金与信任风险 | 幂等键、不可变流水、事务冻结/结算、定时对账 |
| 用户上传侵权素材 | 法律与平台风险 | 协议声明、内容审核、投诉渠道、留存审计记录 |
| 功能范围过大 | MVP 延期 | 坚持两条主链路；视频、批处理、无限画布全部后置 |

## 18. 已确认决策与后续确认项

### 18.1 已确认决策

1. 首发用户同时覆盖国内中小商家和跨境电商团队。
2. MVP 的生图、视觉理解、抠图与安全审核能力统一优先通过 [BananaRouter](https://bananarouter.com/docs) 接入；具体模型与接口能力在 Sprint 0 完成技术验证。
3. MVP 暂不提供用户上传图片“绝不用于训练”的合同级承诺，但必须在隐私政策中如实披露第三方处理方式。
4. 卖点主图接受“生成无字底图 + 提供可复制文案建议”的实现方式，不把模型直接生成准确文字作为 MVP 验收条件。
5. MVP 暂不考虑 AI 生成内容水印和内容凭证；保留普通的人工核验提示。

### 18.2 后续确认项

点数套餐、免费额度、图片存储期限和毛利目标暂不在本阶段定值。研发先实现钱包、点数流水、冻结/结算、免费额度配置和存储期限配置等基础能力；在端到端生图流程首次跑通、可以获取 BananaRouter 实际调用成本时，再向产品负责人确认具体数值和套餐策略。

## 19. 竞品研究与优化结论

> 调研日期：2026-09-07。结论基于参考产品公开页面和未登录工作台，实际付费能力、生成质量与后台逻辑不在本次验证范围内。

### 19.1 产品对照

| 维度 | 三万图 AI | PixPix | 本产品决策 |
|---|---|---|---|
| 首层入口 | 全能、电商、视频、批处理、SKU、替换等模式 | Agent、图片、视频和热门任务工具 | MVP 仅展示图片相关任务；先选交付目标，再进入聚焦编辑器 |
| 通用生图 | 输入框、技能/Agent、尺寸、模型 | 输入文字或参考图，支持 `@` 引用，模型与尺寸集中配置 | 保留简洁输入；模型进高级设置；素材 `@` 引用列为 P1 |
| 电商图 | 主图、详情页、主图+详情页；平台、语言、数量、对标图 | 商品套图、A+/详情页、爆款复刻、产品精修、换色、穿戴等独立工具 | P0 保留白底、场景、卖点和详情单页；智能套图与生成式编辑进入 V1.1 |
| 套图结构 | 可一次产出主图和详情页 | 智能匹配 Listing 套图或自定义图片类型与数量 | V1.1 提供智能/自定义两种结构；底层数据模型在 MVP 预留 `task_type/module_type` |
| 详情页 | 设置主图与详情页数量 | 先选 A+ 规格，再选择首屏、核心卖点、场景、多角度、规格等模块 | MVP 详情单页必须选择一个内容模块，完整 A+ 多页编排进入 V1.1 |
| 参考图 | 对标图主要参考设计风格 | 强调构图、色彩、主体、风格和商业表达的视觉拆解 | P0 展示六维视觉拆解标签，并允许用户取消不希望参考的维度 |
| 结果处理 | 预览、项目和资产沉淀 | 局部重绘、放大、扩图、消除、移除背景、改变视角、裁剪 | P0 做无模型成本的裁剪/平台尺寸适配；生成式编辑进入 V1.1 |
| 灵感复用 | 提示词资产库 | 案例社区、发现灵感、一键同款 | P1 做模板化“一键同款”，只复用公开视觉策略，不暴露原素材和提示词 |
| 模型策略 | 模型可选择 | 模型可选，也可交给 Agent 自动匹配 | 默认自动路由，专业用户在高级设置中手动选择 |

### 19.2 PixPix 值得吸收的设计

1. **以任务交付物组织入口**：用户看到的是“商品套图、详情页、产品精修”，而不是一串模型名。该思路已转化为任务首页和聚焦编辑器。
2. **先给结果预期，再要求填写参数**：工具页用清晰案例说明上传什么、能得到什么，可降低首次使用的不确定性。每个任务入口因此必须带输入/输出示例。
3. **套图结构可解释**：智能匹配适合新用户，自定义结构适合有明确 Listing 规范的专业用户。该能力进入 V1.1，不与 MVP 的单图闭环争抢研发资源。
4. **详情页按内容模块选择**：相比只填写“详情页需求”，模块选择更容易生成稳定结果，也便于计费和重试，因此将单模块选择提前到 P0。
5. **结果即下一步输入**：生成后直接进入裁剪或派生编辑，比回到首页重新上传更顺畅。MVP 先完成裁剪和尺寸适配，并在资产模型中保存派生关系。

### 19.3 不在 MVP 照搬的部分

- 不公开展示尚未交付的视频、穿戴、爆款复刻和大量实验性工具，防止入口膨胀。
- 不把 Agent 作为独立概念要求用户学习；MVP 的任务拆解、提示词编排和模型选择由系统在后台完成。
- 不建设开放社区，先用审核过的官方案例和模板验证“一键同款”的使用率。
- 不一次实现完整商品套图、A+ 长图和生成式编辑，先保证单图质量、商品一致性、任务成功率和成本可控。

### 19.4 最终产品形态

产品采用两种参考思路的组合：吸收三万图 AI 在电商参数、提示词资产和项目沉淀上的完整性，吸收 PixPix 在任务入口、交付预览、内容模块和结果连续编辑上的清晰度。MVP 对外只呈现通用生图与四类电商单图任务；底层按统一项目、资产、任务和派生关系建设，为 V1.1 的智能套图及 V1.2 的无限画布复用同一数据底座。
