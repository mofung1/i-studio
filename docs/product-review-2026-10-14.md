# 产品与界面优化建议 · 2026-10-14

面向个人用户的 AI 生图工作台。检查了当前工作台、资产、灵感、电商工具与服装组图页面，并结合设置页的近期验证、前后端实现和公开项目资料整理建议。本次只实现用户明确要求的弹窗文案删除，下面的功能均为待讨论方案。

## 本次已调整

图片反推弹窗不再显示“图片会发送至 DeepSeek 进行分析”，其他已配置服务也不再显示这条普通提示。识图服务不可用时，仍显示原因与“配置识图服务”入口。

Next.js 生产构建与类型检查通过，Web 容器已更新。登录本地测试账号打开真实弹窗后，确认普通服务提示段落已消失；没有提交新的识图或生图请求。

## 当前产品基础

已有通用生图、五类电商工具、服装逐图规划、模型与内置 Prompt 配置、灵感分类管理、双语图片反推、历史参数回填、参考图复用、全屏缩放和平移、本地裁剪及服装 ZIP 下载。这些能力已经覆盖较完整的首次创作流程。

下一步的重点是让作品更容易查找、比较、继续修改和长期保存。建议按“完成一张图 → 挑选好图 → 归档 → 继续创作”的顺序完善产品。

## 优先补齐的基础体验

| 已确认的现状 | 建议 | 验收标准 |
| --- | --- | --- |
| 资产页默认读取最近 50 条任务；服务端只支持 limit，最多 200。页面“加载更多图片”只展开已取回任务中的图片。历史抽屉分别读取最近 40 / 60 条。 | 增加稳定的游标分页，资产与历史共用完整查询能力。 | 超过 200 条记录后仍可找到最早作品；新增任务不会让翻页重复或漏项。 |
| 受保护图片使用原图 Blob，缓存仅按 120 张限制，没有总字节预算。 | 列表使用独立缩略图；大图预览再读取原图。增加缓存字节预算与回收策略。 | 大量 4K 作品浏览仍保持响应；缩略图与原图加载互不阻塞。 |
| 生图有排队、生成、等待供应商和失败状态，但没有可操作的任务中心；当前生图没有取消路由。 | 显示等待时长、已完成张数、具体阶段，提供排队取消与查看结果入口。 | 切页、刷新后能查到全部未完成任务；进度来自实际任务状态，不显示虚构百分比。 |
| 异步供应商任务 ID 目前用于运行中的轮询，没有持久化的恢复映射。旧任务超时后不能重新查询原任务补回结果。 | 持久化供应商任务 ID、实际服务、每张图的阶段。增加“重新查询结果”，与重新付费生成区分。 | 超时后供应商实际成功的任务可补回；不会因查询动作重复提交生图。同步服务只提供其实际支持的恢复方式。 |

当前图片展示已优先使用任务输入里的比例、分辨率，不应再把“修改输入设置会改变已生成图片的参数显示”视为仍未修复的问题。生成期间的 Prompt 模板快照也已存在；后续可以进一步持久化实际执行版本。

## 最值得增加的功能

| 优先级 | 功能 | 首版范围与价值 | 工作量 / 依赖 |
| --- | --- | --- | --- |
| 高 | 项目归档与资产搜索 | 按项目收纳图片、素材与提示词；收藏、标签、名称编辑；按提示词、模型、日期、工具筛选；批量下载和移动。方便找回长期作品。 | 中。后端已有 projects 与 projectId 基础，但当前页面没有完整项目管理流程，需要补齐编辑、归档与资产关联。依赖完整分页。 |
| 高 | 私有提示词与创作预设 | 个人收藏提示词、版本记录、变量填空；保存模型、比例、风格组合为预设。反推结果可以先进入个人库，再选择是否成为公开灵感。 | 中。现有灵感 CRUD 与分类已具备；新增的是账号私有边界、预设和版本，避免重复建设。 |
| 高 | 双图对比与单图继续创作 | 从最近生成或资产中选两张，支持并排、同步缩放与前后滑杆；保留来源关系；只重做选中图片或服装镜头。 | 中。已有全屏查看与参数回填，可以在此基础上扩展。滑杆同时提供按钮 / 键盘操作。 |
| 高 | 图片编辑 | 从图片预览进入，首版优先做涂抹区域修改、换背景，再扩图与高清放大。把已经接近满意的图继续改好。 | 较大。需要掩膜编辑器与服务能力适配；当前参考图编辑不能等同于掩膜修复。按模型实际支持开放入口，并保留原图和版本。 |
| 中 | 电商商品档案与组图交付 | 保存商品原图、确认的卖点、品牌颜色和模特 / 场景素材；主图、详情、服装共用。增加单镜头补图、详情图排序拼接、按平台尺寸导出。 | 中到较大。逐图规划已具备；商品事实需由用户确认。可编辑文字层单独实现，避免把文字精确排版全部交给生图模型。 |
| 中 | 用量与耗时记录 | 按任务记录服务、模型、张数、耗时和供应商返回的实际用量；用户可配置参考单价和预算提醒。 | 中。供应商未返回费用时，只显示有依据的估算，不把估算当作账单金额。 |
| 中 | 备份与恢复 | 先做可验证的备份脚本、恢复流程与版本标记，再提供设置入口。覆盖数据库、图片、配置与必要密钥；另提供不含密钥的提示词 / 项目交换包。 | 中。当前 README 只有手动备份说明，尚无完整产品操作流程。 |
| 后续 | 项目画布与轻量流程 | 在项目里放图片、提示词和批注，支持来源连线、撤销与保存。后续再接入“分析 → 生图 → 精修”的可复用流程。 | 大。依赖项目、版本关系和可靠任务记录；先验证参考板与多图对比的实际使用需求。 |

优先建议先落地：**完整资产查询与项目归档 → 私有提示词 / 创作预设 → 双图对比和单图继续创作**。任务恢复与缩略图性能可以同步完善。图片精细编辑作为下一阶段的核心新增能力。

## 界面美化方向

保留黑白主色、简洁线性图标和以图片为中心的布局。以下建议属于对当前设计的收敛，不需要重新更换整套视觉语言。

1. **统一组件和间距来源。** 最近设置页的过大空隙来自父容器 gap 与面板 margin 叠加。将页面外边距、卡片内边距、输入框高度、圆角、焦点环和按钮层级集中到共享样式。当前两份主要样式文件约 8,459 行，存在多轮覆盖，应逐页拆分并做视觉回归。
2. **资产页补一条完整工具栏。** 当前顶部仅有图片 / 任务视图切换。加入搜索、过滤、排序和卡片密度；批量选择后显示上下文操作栏。卡片优先显示用户命名，长提示词放入详情，减少整排省略号。
3. **工作台增强挑图效率。** 在现有大图区域增加对比与专注查看入口，最近生成支持收藏标记。常用参数保持紧凑，高级参数按需展开；新编辑操作放在图片旁边的固定工具条，避免新增浮层遮挡图像。
4. **灵感页把展示和个人复用衔接好。** 现有分类侧栏与瀑布流可以保留；没有封面的卡片使用带标题与分类的设计占位。常用操作优先保留“使用”和“收藏”，详情中提供复制、编辑后使用与预设保存。筛选与滚动位置返回时应恢复。
5. **电商工具入口用效果说明能力。** 当前大卡片使用示意图片，有的主体被横向裁切。建议改为清晰的原图 / 结果示例，标明所需素材与产出内容；服装长表单保持上传、图种、拍摄、参数四组，并让高级参数可折叠。
6. **检查低频但容易影响品质的状态。** 统一空态、加载失败与重试；验证浅色 / 深色焦点和禁用状态。对 375px 手机、平板和常见桌面尺寸分别检查顶部按钮溢出、弹窗内容滚动和固定底栏遮挡。

## 参考项目与适用边界

- [InvokeAI Gallery](https://invoke.ai/features/gallery/)：提供 Boards 归档、收藏和图片元数据操作。适合参考“作品组织 + 来源复用”的结构。
- [InvokeAI 项目](https://github.com/invoke-ai/InvokeAI)：提供统一画布、局部编辑和工作流管理。适合研究后续图片编辑与项目画布的交互。
- [Fooocus 项目](https://github.com/lllyasviel/Fooocus)：将变化、放大、局部重绘和扩图围绕输入图片组织。适合参考轻量的“选图 → 修改”流程。
- [ComfyUI 工作流模板](https://docs.comfy.org/interface/features/template)：通过模板承载可复用的工作流。可以借鉴预设与需求说明；本项目的个人用户入口仍应以简单表单和明确操作为主。

这些项目的能力不能直接证明当前配置的远程模型支持同样的编辑功能。图片编辑、种子复现、取消供应商请求和费用统计都应通过具体协议的能力描述与适配实现；UI 只显示已支持的功能。

## 建议的推进顺序

第一阶段完善作品查找、项目归档、共享控件与任务恢复，让现有功能更可靠。第二阶段加入私有提示词、预设、图片对比与单图补图，减少重复创作步骤。第三阶段增加图片精细编辑、电商交付与项目画布，扩展持续创作能力。

每阶段用“能否找到旧作品、能否复用配置、能否保留好图只改一处、能否恢复中断任务”验收。界面改动先提供可查看的页面或原型，再决定较大的布局调整。
