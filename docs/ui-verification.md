# 前端布局验收

样式修改必须检查真实页面的数据加载后状态。单元测试、类型检查、生产构建以及页面宽度不超屏，只能覆盖部分问题，无法排除文字被挤成竖排或吸底操作区遮挡正文。

## 基本步骤

1. 明确本轮影响的页面、子面板和弹窗。修改共享规则时，增加已有使用场景的复查。
2. 在实际浏览器打开页面，等待对应业务组件出现。例如图片反推需等待「保存配置」，网站配置需等待表单，列表需等待 `aria-busy="false"`。不要把加载中或接口错误页面当作完成验收。
3. 覆盖桌面、平板和手机，建议至少 1440、768、375、320px；检查明暗主题以及正常、未保存等相关状态。
4. 查看页面顶部、长表单中段和底部操作区。除了超屏，还检查文字阅读宽度、按钮内容、控件重叠、底栏遮挡、正文滚动和操作区可见性。
5. 保存实际截图和测量记录；只读检查优先，提交、保存和故障测试使用隔离环境，除非用户任务本身已明确授权对应业务修改。

## 后台操作区检测

`web/scripts/admin-layout-audit.mjs` 导出 `auditAdminLayout()`，只读取 DOM 和计算样式，不请求 API、不修改页面。可在已加载的后台页面中执行，返回 `ready`、`issues`、`measurements`。

检测范围包括：

- 反推配置未加载完成；
- 页面或底栏横向溢出；
- 状态文字被压缩成窄列，包括宽度为 0 的 flex 子项；
- 过高底栏；
- 页面 sticky/fixed 底栏覆盖前面的正文；
- 操作按钮内部内容溢出或相互重叠。

通过条件是 **`ready === true` 且 `issues.length === 0`**。仍需目视检查截图；检测器不覆盖所有卡片、表格内容或所有可访问性要求。

在 Codex 的 CUA 浏览器中，先正常选择浏览器、打开页面并等待真实组件，再读取脚本，去掉导出关键字，以只读表达式执行：

```js
const source = (await fs.readFile(absoluteAuditPath, "utf8")).replace(
  /^export /m,
  "",
);
const result = await tab.playwright.evaluate(
  "(() => {" + source + "; return auditAdminLayout(); })()",
);
```

文件读取仅用于加载检测源码，页面交互继续使用 CUA。不要通过 evaluate 修改 DOM、样式、业务数据或登录状态。

检测器逻辑回归：

```bash
pnpm -C web test scripts/admin-layout-audit.test.mjs
```

这条命令验证检测器能识别已知故障，不启动真实浏览器，因此不能单独作为页面样式通过的依据。

2026-10-26 的实际回归先在修复前页面识别出 0px 状态宽度、约 319px 底栏和正文遮挡，再用同一脚本验证修复。证据见 后台底栏修复报告（历史记录，可从 Git 历史查看）。
