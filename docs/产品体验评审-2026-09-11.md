# iStudio 产品体验评审（PM 视角）

> 评审日期：2026-09-11
> 评审范围：`docs/PRD-AI电商创作平台-MVP.md`、`apps/web`、`apps/server`、`packages/contracts`、`UI/` 原型、`development-progress/`
> 评审角度：端到端使用流程是否闭环、操作体验是否可信、工程协作是否支撑下一阶段

## 0. 一句话结论

**主链路"上传 → 生成 → 下载"已经跑通，但产品目前是一个"能演示、还不能交付"的状态：**
流程上有 4 处断点导致新用户走不到第二次生成；工作台里 AI 优化、商品分析、视觉拆解、点数余额、最近项目都是硬编码假数据，用户建立的是错误预期；PRD 中作为商业模式基础的计费闭环完全未实现。

建议按"**先拆假数据、再补闭环、最后补能力**"的顺序推进，而不是继续横向加功能。

---

## 1. 使用流程上的断点

### 断点 1｜游客浏览是假的，登录后上下文全丢（P0）

| 位置 | 现状 |
|---|---|
| `apps/web/components/workbench.tsx:157-159` | 未登录直接 `router.replace('/login')` |
| `apps/web/app/login/page.tsx:21` | 登录后写死跳 `/workbench?mode=general` |
| PRD `AUTH-05` | 游客可浏览入口与示例；上传或提交前才要求登录，**登录后保留当前配置** |

后果：用户从首页"白底精修"卡片进入 → 被踢到登录页 → 登录后被扔进"通用生图"，商品任务选择、首页输入框写好的描述、模型/比例/数量全部丢失，需要重新走一遍。这是新用户第一次流失最容易发生的地方。

**建议**
1. 工作台改为"参数可编辑、提交时才拦截登录"的模式（游客态保留完整 UI，仅生成按钮触发登录）。
2. 登录页支持 `?next=` 回跳，并把当前工作台参数（mode/task/prompt/model/ratio/resolution/count/projectId）整体带过去。
3. 登录后回落到原 URL 而不是固定 `mode=general`。

### 断点 2｜首页到工作台只是"参数交接"，不是"意图交接"（P0）

- 首页 hero 是一个 GET 表单（`home-page.tsx:54-60`），提交后进入工作台，但工作台**不会自动提交**，用户还要再点一次"生成"。
- 4 个电商工具卡片 → 工作台后，用户仍需自己判断"要传什么、会得到什么"。PRD `WB-07` 要求任务入口必须展示"输入素材 → 输出结果"和输出类型说明，现在只有一张 Unsplash 图 + "效果预览"字样。
- 首次使用者在上传商品图之前，没有任何地方告诉他：白底图要 1 张商品图、卖点图要填卖点、详情页要选一个内容模块。

**建议**：任务入口区做"输入/输出"双栏示意（可直接复用 `UI/` 原型已有设计），并在工作台空态画布上用一行 checklist 替代现在的大图占位。

### 断点 3｜结果页是断头路，没有复用闭环（P0）

生成完成后只有一个动作：**下载**（`workbench.tsx:463`）。任务详情页同样只有下载 + 原参数重跑（`tasks/[id]/page.tsx:98-101`）。

PRD 中以下 P0 需求均未实现：创建变体（TASK-06）、重新生成并展示本次价格（TASK-07）、ZIP 批量下载（TASK-08）、平台尺寸裁剪适配（TASK-10）、收藏（TASK-05）。

这直接打击北极星指标"每周成功导出的电商图片数"——用户导出一次后，没有任何引导他做下一张的钩子。

**建议**：结果区一级操作补齐 **下载 / 加入项目 / 创建变体 / 重新生成**，批量下载与裁剪放"更多"。其中"创建变体"实现成本最低（复用原 input 重新提交），建议优先。

### 断点 4｜结果无法沉淀，资产中心不参与创作（P1）

- 上传的素材进了资产列表，但工作台**无法引用已有资产**，每次都要重新上传（ASSET-04 未实现）。
- 生成结果只写入 `generation_tasks.result_images`，**没有落 asset 记录**，因此无法收藏、复用、做变体。
- 项目卡片点击固定跳 `task=scene`（`projects/page.tsx:100`），与用户真实意图无关。
- 没有独立资产中心页，资产与项目挤在同一页且无类型/时间筛选（ASSET-03）。

### 断点 5｜首屏全是硬编码假数据（P1，信任问题）

| 位置 | 假数据 |
|---|---|
| `home-page.tsx:87-92` | "Aero H1 秋季上新 · 场景图 · 12 个资产 · 刚刚"，对任何用户都一样，点击进空工作台 |
| `home-page.tsx:95-102` | 发现灵感 3 张图，点击无任何行为 |
| `top-navigation.tsx:28` | 点数余额写死 `1,280`，点击无反应 |
| `top-navigation.tsx:29` | 通知铃铛无功能、无未读态 |

PRD 9.4 要求每个页面覆盖"空数据、加载、无权限"等状态，目前首页只实现了"看起来有数据"这一种。

**建议**：没有数据时显示真实空态 + 引导（如"上传第一张商品图"），不要造数据。发现灵感可暂时隐藏或标注"即将上线"。

## 2. 工作台操作体验问题

### 2.1 误导性呈现（P0，涉及诚信）

**a) 生成中用 Unsplash 图假装"正在生成"**
`workbench.tsx:453-459`：生成中展示的仍是那张 Unsplash 参考图，配 scan-line 动画；进度条 `stage-track` 是静态 DOM，不随 `queued / processing / waiting_provider` 变化，直到轮询返回 `succeeded` 才切换。
违反 PRD `TASK-02`（不伪造精确进度）与 `WB-07`（示例不得冒充真实生成结果）。用户会以为图已经在出来了。

**b) AI 优化、商品分析、视觉拆解全是假的**
- `improveDescription`（`workbench.tsx:339-344`）只把 requirements 替换成一句固定文案，不能撤销；通用模式下点击什么都不做但仍提示"已优化画面描述"。
- 视觉方向模块（`workbench.tsx:417-422`）：六维标签与"智能匹配·基于商品图推荐当前方向"是硬编码，配图是 `taskMeta.scene.image`（Unsplash），**不是用户上传的参考图**；且电商模式下根本没有参考图上传入口。
- 商品图在后端只作为 base64 内联图传给模型（`queue.go:145-179`），没有任何分析结果，也没有可回看的商品分析报告（PRD 8.4.4）。

**建议的最短改造**：不做真分析可以，但必须把这三个模块标注为"示例/预览"，或暂时下线。宁可少一个功能，也不要让用户以为系统在理解他的商品。

### 2.2 参数与文案不一致（P1）

| 问题 | 位置 |
|---|---|
| 通用模式文案"最多 4 张"，实现只取 `files[0]` | `workbench.tsx:385-388` |
| 商品模式文案"支持 1-3 张"，实现只能 1 张（PRD 要求 1-10） | 同上 |
| 风格、参考强度用 `defaultValue` 不受控，且未进 payload（硬编码 `unspecified` / `medium`） | `workbench.tsx:407-408, 249-259` |
| 参考强度因 `hasReferenceImage` 判断长期禁用 | `workbench.tsx:408` |
| 商品名称取文件名、兜底成 `'Aero H1'`；类目写死"其他"，用户不可填 | `workbench.tsx:266` |
| 卖点靠 `requirements.split(/[\n，。；]/)` 从一段文本里切，规则对用户完全不可见 | `workbench.tsx:230-233` |
| 模型第一项写"Auto · 推荐"，实际 value 是 `gpt-image-2`，无自动路由 | `workbench.tsx:438` |

商品名称和类目会直接进提示词编排，比比例、数量这类参数重要得多，但现在反而是唯一不能填的。

### 2.3 状态恢复与并发（P1）

- `generationTask` 只存在组件 state（`workbench.tsx:134`）：**刷新页面或关闭工作台，结果就没了**，只能去任务页找回。PRD `TASK-01`（刷新/换设备可继续查看）与 `WB-02`（草稿 2 秒防抖自动保存）均未实现。
- 生成中按钮 disabled（`workbench.tsx:439`），与 PRD 9.2"生成中允许继续编辑新草稿，不阻塞整个工作台"冲突。
- 无 SSE，前端 3 秒（工作台）/ 5 秒（任务详情）轮询。
- 后端**单 worker 串行消费**队列（`queue.go:45-143` 只有一个 goroutine），且无自动重试（PRD TASK-04 要求最多 2 次）、无部分成功（一张失败整任务失败）。多人排队时耗时线性叠加，PRD"首次成功生成 P50 ≤ 180 秒"在并发 3~4 个任务时就会破。

### 2.4 结果呈现与下载（P1/P2）

- 任务详情把原始 input JSON 直接 `<pre>` 出来（`tasks/[id]/page.tsx:100`），用户看到 `{"mode":"commerce","taskType":"scene"...}`。PRD `TASK-09` 要求展示模型、种子、尺寸、耗时、费用——现在是"有记录没展示"。
- `AuthenticatedImage` 加载失败静默（`.catch(() => undefined)`），只留一块空白，无重试、无错误提示（`authenticated-image.tsx:34`）。
- 下载用 blob + 立即 `revokeObjectURL`（`authenticated-image.tsx:44-48`），无进度、无成功/失败反馈；下载文件名固定 `.png`，结果是 jpeg 时扩展名错误（`workbench.tsx:463`）。
- 无 ZIP 批量下载。

### 2.5 账号与合规（P0/P1）

- **完全没有登出入口**：全仓搜不到 logout 实现，用户只能清 localStorage。共享电脑上是个实际问题。
- 注册页无用户协议/隐私政策勾选（PRD `AUTH-02` P0），也没有这两个文档页面（PRD 12.3 要求）。
- **点数/报价/流水完全缺失**：PRD 的商业模式（点数制）与"提交前费用预估"（`WB-03`）、余额、流水均未实现，顶部余额是假数字。这是上线前必须补的硬缺口。
- 无内容安全审核接口（PRD 8/10.5），无运营后台（PRD 8.10）。

### 2.6 移动端（P2）

`globals.css` 有 780px / 520px 断点，基础响应式在；但 PRD `WB-05` 要求的 <768px 单栏分步 + 吸底生成按钮未实现（`UI/` 原型 README 里已写明该设计，正式项目没跟上）。

## 3. 项目自身（工程与协作）可优化

1. **`UI/` 原型造成"双重真相"**：它是独立 npm/vite 项目（自带 `package-lock.json`、`node_modules`），README 声明"不作为运行入口"，但里面的资产中心、灵感复用、状态清单比正式项目更完整，评审时极易被当成已交付能力。
   → 建议重命名为 `docs/prototype/` 或在 README 顶部放一张"原型能力 vs 已实现"对照表。

2. **PRD 与实现之间缺少追踪**：PRD 有 100+ 条编号需求（`AUTH-01`…`TASK-11`、`ASSET-01`…），但 20 份 `development-progress` 记录没有一份按需求编号回写覆盖情况。
   → 建议补一张"PRD 需求 → 实现状态"覆盖矩阵，作为后续所有评审的唯一事实源。

3. **进度记录粒度是"技术批次"而非"用户可感知能力"**：20 份文档全是技术视角（"Go API 后端切换"），看不出用户侧闭环走到哪。
   → 建议每份加一行"用户可验证的行为"。

4. **启动配置自检缺失**：`pnpm dev:test` 一键脚本很好，但 AI key / DB / Redis 未就绪时只能在前端按钮上看到"检查 AI 服务…"。
   → 建议脚本启动时直接打印三项自检结果。另外 README 里"脚本会创建缺失 env"与"首次运行前手动 cp"两种说法并存，需统一。

5. **缺端到端冒烟**：交付验证只有 typecheck / test / build / go test，没有覆盖"上传 → 生成 → 下载"的自动化冒烟（可用 mock provider）。当前唯一能验证主链路的方式是花真钱跑一次。

6. **后端结构风险**：`main.go` 729 行同时承担路由、鉴权、任务、资产、项目，且 `db == nil` 的内存 fallback 分支遍布全文件。
   → 更严重的是 `main.go:60-62`：数据库不可用时只打印一行日志就降级到内存态，任务会静默丢失。建议拆分为 `auth / tasks / assets / billing`，并移除生产路径上的内存降级。

## 4. 建议的迭代顺序

### 第一批（止血，建议 1 周）——目标：让产品"可信"

1. 下线或标注所有假功能：AI 优化、视觉拆解/智能匹配、最近项目、发现灵感、点数徽标、通知。
2. 生成中状态改为真实状态驱动：移除 Unsplash 假图与静态进度条，改为状态文案 + 不确定进度指示。
3. 补登出入口 + 登录回跳（`?next=`），保留游客态参数。
4. 修文案与实现不一致：上传张数、模型"Auto"、商品名称/类目改为可填。
5. 首页改真实空态与引导。

### 第二批（补闭环，建议 2~3 周）——目标：让产品"可用"

6. 结果区补齐：创建变体、重新生成、加入项目、批量下载（ZIP）、下载反馈与错误提示。
7. 生成结果落 asset 记录，打通"资产 → 新任务"复用。
8. 工作台状态恢复：任务 ID 写入 URL，刷新可恢复；草稿本地保存。
9. 后端队列：多 worker + 自动重试 2 次 + 部分成功；单 worker 是当前最大的性能隐患。
10. 任务详情参数可视化（卡片式展示模型/尺寸/耗时/费用），替换 JSON。

### 第三批（补商业模式，建议 2 周）——目标：让产品"能上线"

11. 点数体系：报价单、余额、冻结/结算、流水页、失败退回。
12. 注册协议勾选 + 用户协议/隐私政策页。
13. 内容安全审核接入与拦截提示。
14. 运营后台最小集（用户/任务/成本）。

### 工程侧并行项

- PRD 需求覆盖矩阵
- `UI/` 原型定位澄清
- 端到端冒烟（mock provider）
- `main.go` 拆分与内存降级移除

## 5. 优先级汇总

| 级别 | 问题 |
|---|---|
| **P0** | 登录后上下文丢失；结果页无复用闭环；生成中用假图伪造进度；AI 优化/商品分析/视觉拆解为假功能；无登出入口；无点数计费；注册无协议勾选 |
| **P1** | 首页硬编码假数据；结果不落资产、资产无法复用；参数文案与实现不一致（上传张数/模型/商品名称类目）；刷新丢失任务状态；单 worker 队列无重试；任务详情展示原始 JSON；图片加载失败静默 |
| **P2** | 移动端单栏分步与吸底按钮；ZIP 批量下载；下载文件名与格式；PRD 覆盖矩阵；`UI/` 原型定位；端到端冒烟 |
