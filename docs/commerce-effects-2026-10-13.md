# 电商工具真实出图测试与改进

日期：2026-10-13。覆盖商品主图、商品详情、爆款复刻、产品精修，以及服装组图中的商品图与模特上身。

## 测试方法

按用户授权最多生成 12 张：六个场景各生成一张改进前、一张改进后的图片，12 个任务全部成功，没有额外付费重试。使用独立测试账号，不把测试图片混入用户的资产列表。

两组使用相同的已配置 GPT Image 2 接口、素材、用户需求、模块及拍摄规划，均申请 2K；主要变化为后端生成指令。商品为项目已有的八宝粥桶照片；服装为低清白色印花 T 恤；人物为灰发、白胡须、戴眼镜的公开模特照片；复刻参考为红底鞋子构图。

这是每个场景每组一张的样例测试，不能推断长期成功率、多品类效果、整组一致性或性能提升。详情只测试一个卖点模块，服装商品只测试正面图，复刻只真实测试高度复刻。其余模块的指令约束通过自动回归验证。

本地 [图片对照页](../artifacts/commerce-eval-2026-10-13/index.html) 可放大查看原图，[任务结果](../artifacts/commerce-eval-2026-10-13/results.json) 与 [测试参数](../artifacts/commerce-eval-2026-10-13/cases.json) 保留原始记录。图片和页面存放在被 Git 忽略的 `artifacts/commerce-eval-2026-10-13/`，不随代码仓库分发；其中不包含账号凭据或供应商密钥。

## 已实施的改进

- 为四种常规电商任务分别构建生成指令；即使提供自定义提示词，也保留素材角色、商品外观与文字约束。
- 商品原图只提供商品外观，爆款参考只提供构图、布光和背景。按实际附件顺序标明多张图片的用途，避免把参考商品混入结果。
- 主图要求完整轮廓与必要边距；没有明确模块时默认制作单张干净首图。详情的首屏与卖点模块使用独立说明，AI 帮写与实际生成采用相同的模块方向。
- 精修要求局部编辑，保留机位、材质、包装与原场景。未选精修项时仍有基础调整要求，避免变成重新拍摄的广告图。
- 规格、评价、认证、促销、包装内容及尺码模块只采用用户提供的信息；未知信息不生成数字、认证或配件事实。
- 服装商品图要求完整领口、袖口与下摆，细节图允许按规划特写；模特默认规划按照片可见身体范围取景，强调原人物特征与服装印花保留。
- 修正上传数量与复刻说明。电商结果区显示图片加载后的实际像素，供核对所申请的清晰度。
- 更新默认 Prompt AI 指令；用户已保存的模板继续保留，不覆盖自定义内容。实际生图的任务约束独立生效。

## 仍存在的限制

服装原图只有约 508 × 492 像素。两组都能保留大致蓝橙图案与标志，但印花中的细小文字仍被重绘；产品精修也不能保证包装字形和纹理的像素级还原。需要准确字标的商品宜提供高清正面素材，并在发布前核对；生成式编辑本身无法靠提示词保证完全保真。

详情图仍出现碗和谷物道具，不能据此确认商品的配料或成分。后续若要严格限定道具，需要增加明确的商品资料和使用范围，而不能让模型补全事实。

两张改进图实际尺寸低于申请的 2K。请求仍分别发送 `2048x2048` 与 `1536x2048`，图片保存过程没有缩放；此次兼容接口返回的成片尺寸不完全稳定。保留原始文件并显示实际像素，不把放大后的图片标记成模型原生 2K，也没有为此额外付费重试。

## 验证

- 后端 `go test -race ./...` 通过，包含独立 PostgreSQL schema 测试；覆盖自定义提示词约束、参考强度区别、空精修选项、模块事实要求、多图附件顺序和 AI 帮写模块上下文。
- 前端类型检查、26 项单元测试、前后端 Docker 生产构建通过。
- 隔离浏览器测试覆盖六个场景的素材上传、选项与请求参数、服装规划编辑确认、模特必填校验，以及结果实际像素显示。
- 375 / 768 / 1440 宽度下无页面横向溢出，浏览器无脚本错误。页面验证的六次提交全部使用模拟接口，不计入真实出图且不调用供应商。
