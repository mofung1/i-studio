# 运营模式部署与测试

前台面向注册用户，运营后台位于 `/admin`。本轮开发不执行 Git 提交或推送，开发者测试后自行提交。

## 首次启动

```bash
docker compose -f docker/docker-compose.yml up -d --build
```

默认前台为 `http://127.0.0.1:33000`，后台为 `/admin`。

推荐在 `server/.env` 设置部署者自己的管理员用户名和强密码：

```dotenv
ADMIN_USERNAME=your_admin_username
ADMIN_PASSWORD='your_own_strong_password'
```

密码需要 12–128 位。示例文件保留空值，不提供可复用的通用默认密码；本地开发环境可由部署者生成随机密码。含 `$`、空格或 `#` 的密码建议使用单引号包裹，防止 Compose 插值或注释解析。

```bash
docker compose -f docker/docker-compose.yml up -d --build --no-deps api
```

首次启动自动在 `admin_users` 中创建独立后台账号，不创建前台账号或积分钱包。前台使用 `users`，前后台允许同名、使用各自的密码。后台登录入口是 `/admin/login`，前台登录入口是 `/login`；两端会话不能互换，退出一端不会退出另一端。后台会话有效期 8 小时，前台 7 天。

修改环境管理员的用户名或密码后重建 API 容器，只更新后台身份并立即撤销其旧会话，前台账号、素材和余额保持原有归属。清空两项后解除环境绑定，后台账号仍保留。后台用户列表只管理前台用户的状态和余额，不提供授予管理员功能。

也可使用部署命令创建或重置独立后台账号，无需前台注册。密码可从 `ADMIN_PASSWORD` 读取，或通过标准输入提供，避免放在命令行参数中：

```bash
# 使用容器已有的 ADMIN_PASSWORD
docker compose -f docker/docker-compose.yml exec api istudio-server admin --username your_username

# 交互输入，不记录在 shell 历史中
read -r -s -p '后台密码: ' ISTUDIO_ADMIN_PASSWORD
printf '%s' "$ISTUDIO_ADMIN_PASSWORD" | docker compose -f docker/docker-compose.yml exec -T api istudio-server admin --username your_username --password-stdin
unset ISTUDIO_ADMIN_PASSWORD
```

本地 Go 开发环境在 `server` 下运行 `go run ./cmd/server admin --username your_username --password-stdin`，从标准输入传入密码。由环境绑定管理的账号应通过 `.env` 修改，避免下次启动覆盖手动设置。修改 `.env` 后，本地重启 Go API；Compose 需要重建容器，单纯 `restart` 不会重载 `env_file`。

旧版本升级会一次性复制已有管理员的身份与密码哈希到独立后台表，并把原前台身份保留为普通用户。迁移不会移动或清除资产、余额、流水；初始登录密码沿用升级前的值，之后后台改密只影响后台。旧会话需重新登录。建议上线前分别设置不同的前后台密码。

AI 地址、密钥和提示词通过后台持久化。`.env` 不再配置 DeepSeek / Banana Router；历史迁移兼容代码仍保留，已迁移的本地旧变量可删除。不要删除 `AUTH_JWT_SECRET`、`AI_CONFIG_ENCRYPTION_KEY` 或存储中的对应密钥文件。

## 后台配置顺序

1. **AI 与网站配置**：添加 Image AI 通道，配置真实模型、协议、地址、密钥和超时；按需添加支持 Vision 的 Prompt 服务，维护系统模板、反推及网站名称与 Logo。
2. **模型与定价**：为通道创建前台模型，填写对外名称和每张价格，确认后上架。一个通道可对应不同的公开模型，用户只能使用上架且通道可用的模型；免费模型必须明确将单价设为 0 并上架。
3. **运营设置**：设置积分名称（默认「积分」）、注册赠送、是否开放注册、单用户并发任务数、每小时生成和辅助请求上限。
4. **用户与余额**：搜索用户，增加或扣减余额，必须填写原因。正数增加、负数扣减，可用余额不能扣成负数，也不能扣减生成中预留的部分。可停用或启用前台账号；后台身份通过部署配置和命令维护。
5. **运营概览 / 生成任务 / 操作日志**：核对任务状态、预留、实扣、退款，以及后台变更记录。后台任务列表不返回用户图片或完整输入。

普通用户通过个人中心 `/account` 查看余额与最近 100 条流水；前台没有共享配置入口。旧 `/settings` 路由转到个人中心，旧灵感管理链接转到有权限检查的后台。旧管理 API 同样只接受独立后台会话，手动输入旧地址也不能绕过。

### 图片反推配置

在「AI 与网站配置 → AI 服务」中添加实际支持图片输入的 Prompt 模型，填写地址、模型和密钥，启用服务并勾选「支持图片识别」。此勾选只声明模型能力，不会让纯文本模型获得识图能力。

在「图片反推」中选择该服务，或跟随支持识图的默认 Prompt 服务。专门指定识图服务后，切换默认 Prompt 服务不会影响反推。这里复用 AI 服务的密钥，不需要重复填写；读取和保存使用独立后台会话，无需登录前台账号。

- 分析超时默认 120 秒，可设 15–600 秒，反推时覆盖服务通道超时，不影响生图等待时间。
- 图片细节支持自动、精细、快速，实际效果和用量由供应商决定。
- 临时原图和记录默认保留 24 小时，可设 1–168 小时；已保存的灵感及封面会保留。
- 「还原画面」与「只提取风格」使用独立系统模板，可直接从反推面板进入编辑。停用某模板后，该模式无法分析。
- 配置只对新建分析任务生效。恢复推荐参数保留已选服务。服务状态表示配置条件满足，不代表已进行真实接口连通测试。

后台使用绿色表示保存、启用、完成，红色表示停用、删除、失败，琥珀色表示等待或未保存。文字标签同时保留，前台工作台保持原有配色。

## 积分结算

金额以整数保存，100 个最小单位等于 1 积分，前后台最多显示两位小数。

- 单价 1.25，生成 4 张：提交时从可用余额预留 5。
- 保存 4 张：消耗 5，预留清零。
- 只成功保存 2 张：消耗 2.5，退回 2.5；完全失败退回 5。
- 供应商多返回、重复返回或没有可归属资产的图片不会额外扣费。
- 任务、预留和流水在同一数据库事务中创建；结算与结果同事务提交。并发请求锁定用户账户，余额不足返回错误。
- 同一提交编号重复请求返回原任务，参数不同返回冲突；后台调整同样支持幂等。浏览器遇到任务创建响应中断时自动核对原提交，不依赖当时表单或剩余余额。
- 提交时冻结通道、加密密钥、系统提示词和单价，后台后续修改只影响新任务。价格在确认前变更会要求前台重新确认。
- 删除生成记录、删除图片或移动资产不会删除余额流水，也不会再次退费。
- 提示词优化、图片反推和服装分析首版不另扣积分，共用辅助请求次数上限。后台连接测试由管理员主动发起，会产生真实 API 用量，不扣前台余额。

供应商 API 费用和用户积分是两套账。上游已经收费但没有交付可用图片时，用户积分仍退回，平台承担 API 费用。首版不包含在线支付、自动充值、兑换码、套餐或货币结算。

## 持久化与恢复

必须使用 PostgreSQL，连接失败时不启动 API，不允许回退到内存余额。Redis 只是任务通知渠道：数据库中的排队任务会每 15 秒重扫；同一任务只能被一个工作器领取。处理中任务每 30 秒续租，租约为 2 分钟。服务中断并过期后按已保存图片结算，其余退回，并标记失败，不自动重复调用上游。用户可手动重新生成。

普通切页不会取消服务端任务。当前仍建议同一套数据库运行一个 API 进程；多副本需共享图片存储、签名密钥与 AI 加密密钥，并经过独立部署验证。

升级前备份 PostgreSQL、整个 `STORAGE_ROOT` 和自定义环境变量。旧部署所有账号保留为普通用户，已有账号余额为零；生图通道生成未上架模型，原始配置和私有资产保留，旧预设与版本映射到公开模型标识。迁移只执行一次，不会在重启时重新赠送余额或覆盖定价。既有注册账号不补发新配置的注册赠送。

反向代理部署需要 HTTPS、正确的 `NEXT_PUBLIC_API_BASE_URL` 和 `WEB_ORIGINS`。前端 API 地址在构建时写入，修改后重建 Web。登录/注册按来源 IP 限流（15 分钟 60 次）；设置 `AUTH_TRUSTED_PROXY_CIDRS` 后只从受信任的代理读取 `X-Forwarded-For`，代理必须覆盖外部传入的头，否则保留使用连接来源地址。生产数据库和 Redis 不应开放公网端口。

## 测试清单

1. 普通账号不能读取后台 API、服务地址、密钥和系统模板；首个账号没有特殊权限。
2. 配置两个不同单价模型，确认前台费用估算与账户流水一致；将积分名称改为「创作币」，核对所有余额和费用提示。
3. 发放 10.5，重复提交同一调整请求只发放一次；扣减超过可用余额应失败。
4. 不足余额不能生成；多窗口并发不能透支；重复任务请求只预留一次。
5. 用模拟上游覆盖全成功、全部失败、部分成功、无效图片和网络响应丢失；不需要真实付费请求。
6. 生成中修改单价/通道/模板，不应影响已创建任务；下架后不能创建新任务。
7. 切换页面继续查询；停止工作器并等待租约到期，确认失败结算和退款，重启不重复调用上游。
8. 停用账号后旧登录令牌立即不能调用 API；重新启用前台账号后，停用之前的旧令牌也不能恢复使用。

自动回归使用隔离 PostgreSQL schema 和模拟 AI。前端使用 Vitest / jsdom；后端使用 Go 测试及竞态检测。浏览器画面验收由用户在本地完成。

## 后台列表与操作日志

后台模型、用户、生成任务、操作日志、公共灵感提示词和分类列表统一提供分页，默认每页 20 条，可切换 50 / 100 条，显示页码和总数。配置页面保留完整的配置项。模型、用户、任务和日志按数据库分页读取，不再截断到最近 100 条；分类使用完整分类集合筛选后分页，选择分类及迁移提示词时仍可访问所有分类。

这六类列表统一使用基于 TanStack Table v8 的 `AdminDataTable`，支持固定表头、桌面端固定标识列与操作列、可选列显示、恢复默认列、舒适 / 紧凑行距、骨架屏及空状态。小屏幕通过横向滚动查看完整内容，保留原有绿色 / 红色状态和操作按钮。列和密度调整在当前页面内保留，刷新数据不会重置。

模型、用户、任务和日志的可排序列通过 `sort` 与 `order=asc|desc` 参数在服务端对全部数据排序，再分页；切换排序回到第一页，翻页与刷新保留当前排序。排序字段采用白名单，不直接拼接客户端提供的 SQL 标识。分类先对完整分类集合排序，再选取当前页；灵感提示词保持后台配置的展示顺序。

刷新只重新读取当前页，不显示成功提示，也不会触发账户刷新或新增操作日志。修改每页条数和搜索条件回到第一页；超出范围的页码调整至最后一页。任务和用户列表按创建时间及 ID 稳定排序，日志按 ID 倒序读取。切页重置列表滚动位置，刷新保持当前位置。

后台占满视口，侧栏、顶部导航和分页区域保留在原位，表格及灵感列表独立滚动；表格列标题保持可见。配置与概览在内容区内滚动。模型编辑和余额调整使用弹窗，不占用列表区域。

`GET /v1/admin/tasks?page=1&pageSize=20` 返回 `tasks`、`page`、`pageSize`、`total`、`totalPages`，`pageSize` 限制在 1–100。接口仍只接受独立后台会话，保留结算与退款信息，不返回用户图片或提示词。

`GET /v1/admin/users?q=&page=1&pageSize=20`、`GET /v1/admin/models?page=1&pageSize=20` 和 `GET /v1/admin/audit?page=1&pageSize=20` 返回相同的分页信息，数据字段分别为 `users`、`models` 和 `audit`。用户搜索的总数与当前筛选条件一致。

操作日志覆盖后台成功登录、模型与定价、用户状态、余额调整、运营设置、存储配置、AI 服务、系统提示词、图片反推、网站品牌和灵感提示词 / 分类变更。旧 `/v1/...` 配置兼容接口与 `/v1/admin/...` 使用同一记录逻辑，一次成功写入只记录一次；连接测试记录为“已执行服务连接测试”。读取、刷新、校验失败与权限拒绝不记为成功变更。日志不保存密码、API 密钥或提示词正文，前端显示中文操作名称和完整对象编号。过去已存储的日志可翻页查看，过去未写入的记录无法补回。
