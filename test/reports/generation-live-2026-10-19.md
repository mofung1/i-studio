## 本次修复

- 恢复旧反推记录时，原图会作为新的 File 返回；原有去重只识别同一个 File 对象或相同资产 ID，导致同一原图被再次加入参考图。现在先检查身份和文件大小、类型，再在必要时比对图片字节，复用已选原图。不会因文件名相同而误合并不同图片。
- 页面复测确认参考图保持 1/6，提交任务仍使用原收藏素材 ID，并成功生成。
- 后端补充固定诊断标签，分别记录生成失败和图片持久化失败。日志不直接写入第三方原始错误、签名图片链接或密钥。

## 仍需关注的通道输出尺寸

gpt-image-2 在本次 2K 请求下，方图实际返回 1254×1254，3:4 返回 1086×1448。Gemini 的方图返回 2048×2048。当前代码会向 OpenAI 兼容通道发送对应的 size（方图 2048×2048、3:4 为 1536×2048），并原样保存通过校验的图片字节，没有在结果保存时缩图。因此本次结果表明该 gpt-image-2 通道未按所请求的像素尺寸返回，需结合第三方通道配置进一步核查；本次没有通过本地放大图片掩盖差异。
