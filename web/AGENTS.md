# 前端修改与验收

## 布局与作用域

- 页面内表单操作区和弹窗操作区分别处理。页面按钮组不能直接继承弹窗的全宽、固定或吸底规则；需要复用时，必须明确父容器布局并检查状态文字与按钮各自的空间。
- 优先修改组件原有规则或限制选择器作用域。避免泛化的标签选择器和不断追加高优先级覆盖，尤其注意 `width: 100%`、`flex-shrink`、`position: sticky` 组合。
- 修改公共 CSS、按钮组或弹窗组件后，检查现有的页面表单与弹窗使用场景，不只检查新增功能页。

## 表单与确认提示

- 普通表单提交、切换、关闭和页面离开不增加二次确认或 `beforeunload` 拦截。校验、错误和保存状态在当前表单内呈现。不要使用浏览器 `alert`、`confirm`、`prompt`；回归扫描位于 `scripts/no-native-dialogs.test.mjs`。
- 删除、账号停用、真实收费测试等有实际后果的操作使用统一 `ConfirmDialog`；需要等待选择时可用 `useActionConfirmation`。说明操作对象及后果，取消在前，主操作在最右。
- 修改确认弹窗须检查取消后不执行操作、Escape、焦点返回，以及模型编辑器内嵌确认只关闭自身。业务浏览器只打开和取消收费测试，实际请求用隔离环境或按用户授权执行。

## 样式验收

- 构建和单元测试不能代替实际浏览器布局验收。先等待受影响页面数据加载成功、真实表单或列表出现，再检查；骨架屏、读取失败或权限失效不能计为通过。
- 至少覆盖桌面、平板和手机视口；有主题或状态分支时，检查明暗主题、正常状态与未保存状态。长表单还要检查滚动到操作区后的布局。
- 除页面横向溢出外，必须检查文字是否被压成窄列、按钮内容溢出、控件相互覆盖、页内底栏遮挡正文，以及弹窗正文滚动与操作区可见性。
- 后台底栏可复用 `scripts/admin-layout-audit.mjs` 的只读 DOM 检测。先等待对应页面的实际组件出现，再在浏览器中执行；要求 `ready === true` 且 `issues` 为空，同时检查实际截图。检测器自身的单元测试不代表实际页面已经通过。
- 使用只读操作或隔离数据验收。除非用户的任务明确要求修改相应业务配置或调用付费 AI，不要为样式检查保存业务设置、发放积分、确认删除或发起收费请求。
- 保存截图和测量记录，报告真实覆盖范围及限制；桌面模拟视口不等于真实手机验收。详见 `../docs/ui-verification.md`。
